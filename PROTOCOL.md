# Протокол практического сравнения

1. Участники обозначаются кодами P01, P02 и т. д. без ФИО.
2. До замера фиксируют две среды разработки, версии, расширения и железо.
3. Один обучающий пример для знакомства с интерфейсом не включается в расчёты.
4. Каждому участнику выдают эквивалентный набор NAV-01, NAV-02, EDIT-01, DIAG-01.
5. `classic`: навигация вручную, через список файлов и меню. `modern`: разрешены палитра команд, быстрый переход к символу, подсказки и навигационные элементы; не применяется ИИ-генерация итогового кода, если она не предмет измерения.
6. Для половины участников условия идут A-B, для другой B-A; фиксируют порядок.
7. Одинаковая проверка результата по контрольному листу.
8. Учитывают время, успех, ошибки и удобство по шкале 1-5.
9. Наблюдения после прерываний отмечают отдельно и не смешивают с завершёнными попытками. Перед повтором обеспечивают сопоставимость.
10. В выводе пишут о конкретной группе и заданиях; не утверждают, что показатель эквивалентен продуктивности разработчика в реальном проекте.
