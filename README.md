# Оценка влияния интерфейсных сценариев IDE на выполнение задач

Самостоятельный **учебный инструмент**, разработанный для курсовой Антона «Влияние интерфейсных инноваций инструментальных сред на продуктивность разработчика». Не связан с другими курсовыми.

Программа не измеряет производительность IDE автоматически и не может доказать причинный эффект сама по себе. Она фиксирует **реальные измерения, введённые участниками**, рассчитывает описательные показатели и помогает проводить контролируемое сравнение **classic** (традиционная навигация) и **modern** (быстрый поиск команд/символов и подсказки). Результаты зависят от опыта, сложности задания и соблюдения протокола.

## Быстрый запуск

Не нужны сторонние библиотеки, Python 3.10+.

```bash
python -m ide_study tasks
python -m ide_study timed --participant P01 --task NAV-01 --mode classic
python -m ide_study timed --participant P01 --task NAV-01 --mode modern
python -m ide_study report
python -m unittest discover -s tests -v
```

В режиме `timed` сначала нажмите Enter для начала, выполните задачу **в открытой IDE**, затем нажмите Enter по окончании. Укажите ошибки, успех и субъективную оценку удобства 1-5. CSV появится в `study_data/observations.csv` и **не попадёт в GitHub** по настройке `.gitignore`.

## Задания

- `NAV-01` - поиск функции, рассчитывающей итоговую стоимость.
- `NAV-02` - поиск всех использований функции.
- `EDIT-01` - безопасное переименование идентификатора.
- `DIAG-01` - локализация подготовленной ошибки.

Оба условия должны использовать одинаковую задачу, сопоставимую кодовую базу и одинаковую проверку результата. Для исключения эффекта обучения половина участников начинает с classic, другая с modern; порядок фиксируют в бумажном протоколе. Используйте учебный проект или один и тот же исходный код в обеих IDE. Не подменяйте время решения временем загрузки среды.

## Что выводит отчёт

- Число попыток и процент успешных выполнений.
- Медиану времени **только успешных** попыток и медиану числа ошибок всех попыток.
- Медиану субъективной оценки удобства.
- Парные разницы во времени для одинаковых задач и участников, только если есть по одной успешной попытке на каждое условие.

Это **описательная** статистика. Для вывода об общем влиянии инноваций нужен достаточный набор независимых наблюдений и учёт смешивающих факторов.

## Синтетическая демонстрация

```bash
python -m scripts.demo
```

Она печатает расчёты по **искусственным** данным. Эти числа нельзя представлять как результат исследования пользователей.

## Состав

- `ide_study/model.py` - валидация одного наблюдения.
- `ide_study/protocol.py` - фиксированные сценарии задач.
- `ide_study/storage.py` - сохранение и чтение CSV.
- `ide_study/report.py` - агрегаты и сравнения.
- `ide_study/__main__.py` - интерфейс командной строки.
- `tests/test_study.py` - модульные тесты.
- `.github/workflows/tests.yml` - GitHub Actions (после загрузки репозитория).
- `scripts/demo.py` - только синтетическая демонстрация.

## Размещение на GitHub

Создайте **отдельный** публичный репозиторий (например, `anton-ide-productivity`), распакуйте ZIP и загрузите **всё содержимое папки** с сохранением вложенности `ide_study`, `tests`, `scripts`, `.github/workflows`. Не загружайте архив целиком и не публикуйте личные данные участников. После публикации проверьте вкладку Actions. Ссылка и QR в курсовой должны быть добавлены только после появления настоящего репозитория.
